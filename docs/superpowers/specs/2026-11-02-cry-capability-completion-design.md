# CryENGINE 能力补齐总体设计

日期：2026-11-02

## 1. 目标与范围

本设计承接 `docs/design/cry_style_gameplay.md`。此前标为“范围外”的软件能力，本轮纳入实施。目标是让 Break 对 Cry3DEngine、CryAction、CryAISystem、CryAnimation、CryEntitySystem、CryInput、CryNetwork、CryScriptSystem、CrySoundSystem、CrySystem 的已识别缺口都有可调用、可测试的实现，并完成一条真实集成路径。

这不是逐行复制 CryENGINE 3.1，也不以文件数、函数数或同名类数量声称“源码级等价”。完成依据是本文列出的行为合同、真实测试和文档证据。既有实现不推倒重写，已通过的测试必须继续通过。生产服务部署、没有设备时的真机验证、对全部 CryENGINE 私有行为的穷举兼容不属于代码完成证据，必须继续如实记录。

## 2. 已确认的起点

- `break_game` 已有 Actor 类、生成与销毁、ActionMap、关卡侧车和 Area；`break_ai` 已有高度图烘焙、A*、跟随、视野、行为树和侧向避障。它们仍是独立库。
- 动画已有多层混合、淡入淡出、遮罩、两骨 IK、事件、一维 locomotion、挂点及瞄准/注视槽。
- 物理已有刚体姿态、铰链、滑轨、布娃娃、射线载具、绳索、布料、软体和可破坏物。
- 世界已有植被 CPU 布局、昼夜参数、VisArea/Portal、块驻留意图、VFS 块读取、贴花/体素/道路的顶点打包与基础网格绘制。
- 输入、可靠网络、会话认证、复制、Lua、miniaudio 音频、VFS、任务、profiling、崩溃及编辑器均有既有基础。
- `origin/master` 的 `5db84314` 有 Windows 构建失败；本地 `d8b31350` 另有五个未推送的网格提交。先解决该回归，再扩展功能。

进度补充（2026-11-02）：P0 的测试 fixture 已改为跨平台路径，Linux normal/ASan+UBSan 通过，Windows 结果仍待 CI。P1 的固定物品表、事务式背包和武器状态机已实现并经逐项评审；装备不赠弹、时钟/冷却跨装备保留、失败 tick 完整回滚，最终武器测试 16/16 在 normal/ASan+UBSan/TSan 通过。P2–P12 不因此提前标为完成。

## 3. 方案取舍

### 3.1 采用：纵向可验收子项目

每个子项目完成公共 API、生产实现、失败测试、正常/ASan+UBSan/TSan 验证、使用文档和实际消费者。优势是每一步都有可运行结果，能在现有模块上演进而不制造平行引擎。

### 3.2 不采用：只搭同名接口

空管理器、硬编码示例、只验证结构体大小的测试无法提供游戏能力，不视为完成。

### 3.3 不采用：复刻 CryENGINE 源码结构

Break 的 ECS、C11 API、RHI 和所有权模型与 Cry 不同。复制其 C++ 类层次会破坏现有边界，也不能证明行为正确。

## 4. 共同架构约束

- 引擎核心和新增库使用 C11；编辑器与既有 C++ 边界保持原语言，不引入新的 UI 框架或未经确认的依赖。
- GameThread 独占 World、Actor、AI 查询、行为树、动画和物理的可变状态。渲染、音频和网络只接收命令、快照或 POD 数据。
- 热路径不临时分配内存；容量在创建时确定。容量、深度、输入大小和消息数量均有硬上限，超限返回错误，不静默截断。
- 失败操作事务化：不能留下半创建的 Actor、半个物理约束图、部分替换的 Lua 模块或部分更新的资源。
- 持久身份使用带 generation 的句柄，不把 C 指针暴露给 Lua、网络或持久化数据。
- 新可选库默认不进入 `engine` 核心。集成通过一个明确的新应用目标完成，避免把编辑器、网络服务、音频和脚本强行耦合成单一库。
- 保持 Vulkan 默认、OpenGL 最后降级。新增渲染能力经 RHI；headless 使用确定性 CPU/记录后端验证，不假装产生 GPU 画面。
- 每个子项目先写能因缺少目标行为而失败的测试，再实现；至少检查一项关键行为的变异，不能仅记录“编译时未定义”作为全部 RED 证据。
- 测试项目沿用 CTest 和 `test_framework.h`。文档随功能更新，不能继续描述旧的“未实现”状态。

## 5. 子项目及行为合同

### P0：跨平台构建回归

取得失败 job 的真实编译诊断，修正源因而非屏蔽告警或关闭 Windows 测试。复现同一编译路径，跑网格相关测试和普通/sanitizer 回归。已有的五个本地提交必须纳入验证后再推送。

### P1：游戏对象、物品与武器

在 `break_game` 增加固定容量的物品定义、背包槽、堆叠与事务式转移，以及武器弹匣、备弹、射速、装填和伤害意图。伤害不直接由客户端决定，输出给权威裁决层。覆盖容量、溢出、非法物品、重复转移、中途失败回滚和确定性的 tick。

### P2：Flow Graph 与编辑

新增有界节点图：事件、数学/比较、实体动作、延迟和顺序分支；稳定节点 id、显式端口、环检测、每帧执行预算和确定性事件队列。序列化进行版本、长度、引用和范围校验。编辑器使用 myui 提供节点列表/画布、连接和属性编辑，编辑操作进入现有 undo 命令栈；不把规则引擎改名为 Flow Graph。

### P3：动态 AI 与编组

在 `break_ai` 增加运行时障碍更新所影响的导航区域、版本化查询失效、带速度的局部避障、编组槽位与智能对象预约/释放。动态更新在 GameThread 提交，查询缓存按导航版本拒绝陈旧结果。覆盖动态墙阻路/重新开路、无路径、预约竞争、agent 容量与确定性。

### P4：动画变形、面部、压缩与物理驱动

增加有界 morph target 及权重评估、命名面部表情与曲线、版本化动画量化/解压，并把布娃娃刚体姿态稳定地写回骨架局部 TRS。覆盖空通道、非有限值、越界关节、损坏压缩字节、往返误差及 IK/布娃娃互斥。变形结果接入实际蒙皮输入，而非只存参数。

### P5：物理补全与载具框架

在现有世界上增加锥 twist 等缺少的约束、轮子接触模型/可选轮体及载具控制状态。绳索、布料、软体和破坏继续复用现有实现，不另建平行世界。覆盖约束极限、休眠/唤醒、零惯性、销毁回收和失败原子性；不把任意提高固定上限当作功能完成。

### P6：世界材质、植被和流式呈现

扩展现有 28 字节网格路径所需的材质描述，支持受光表面和纹理绑定；保持旧顶点数据可迁移。植被从 CPU 布局进入实例化绘制并复用 LOD；昼夜写实际着色参数；VisArea 结果进入可见对象提交；流式块进入同一渲染路径。分别用 CPU 合同、fake RHI 和 Vulkan/OpenGL 像素测试验收；没有设备时明确缺证。

### P7：输入反馈与触摸

在 `InputState` 之外以版本化侧车或有界扩展保存多点触摸、手势与手柄反馈请求，避免破坏既有输入 ABI。实现 Linux/Windows 后端能支持的部分，震动经平台句柄异步/命令式提交，GameThread 不直接操作设备私有状态。覆盖按下/移动/抬起/cancel、触摸 id 复用、坐标范围、设备断连与无反馈设备降级。

### P8：在线会话与游戏网络能力

增加有界大厅/房间目录、加入/离开、主机迁移和服务端匹配接口；身份只来自认证会话。实现 UDP NAT 打通的协调消息和本地端到端证据，不承诺任意 NAT 都能穿透。语音使用有界 PCM 帧、序号、抖动缓冲和丢失处理，不在网络线程混音。复制增加按 aspect 的 schema、变化掩码和带宽友好编码，复用现有安全、分片和 AOI。

### P9：Lua 调试、表绑定与 Actor 接线

在独立调试库中实现断点、单步、调用栈、局部变量检查和执行预算协作；调试默认关闭，不能把 `debug` 库暴露给沙箱模块。提供递归深度、节点数和字符串长度受限的表值与稳定 host 句柄绑定。将 Actor 类的 `lua_module` 接到现有 `break_lua` tick，脚本失败不破坏其他 Actor；远程调试继续默认关闭并要求授权。

### P10：音乐、DSP、遮挡和声音事件

扩展现有音频系统：命名声音事件、并发/重触发策略、音乐播放列表与交叉淡化、可组合 DSP（至少滤波、延迟/混响）、射线回调驱动的遮挡和距离衰减。音频回调只消费预分配命令和 PCM 数据，不进行文件 I/O、网络或游戏逻辑。以确定性 PCM 测试 DSP，以 null/fake 设备测试生命周期；只有实际听测时才声称听感通过。

### P11：CVar、XML 与插件

提供注册式 CVar：类型、范围、只读/ Cheat 权限、变更回调和配置存取。实现有界 XML 解析/序列化，拒绝 DTD/实体展开、深度/大小超限和非法 UTF-8，用于定义明确的场景侧车而非无损替代 BSCN。插件经 PAL 动态加载，带 ABI 版本、构建 id、哈希 allowlist 和确定性注册/卸载顺序；不支持热卸载仍被引用的插件。

### P12：实体系统与真实集成

实体类继续由 P1 的注册表和组件组合承担，不引入 Cry 代理 vtable。新增一个明确的可玩应用目标，把 Actor/Lua、输入、AI、动画、物理、世界呈现和声音接到同一生命周期；网络是独立可选通道。提供可重复的场景，验证加载→输入→模拟→渲染/音频命令→保存→卸载。按更新后的边界修正 target contract，不保留“尚未接线”的过期文档。

## 6. 数据流与错误处理

输入事件先归一化为 ActionMap/触摸快照；GameThread 依次执行 Lua/Flow Graph、AI、动画意图和固定步长物理，生成世界与音频快照。RenderThread 只接收带 frame id 的渲染命令和不可变资源版本；AudioThread 只消费有界 PCM/命令；网络回调只验证并排队。跨线程对象不得在快照提交后被写者修改。

非法外部数据返回 `INVALID`，失效句柄返回 `STALE`，容量满返回 `OVERLOAD`，线程归属错误返回 `REJECTED`，资源不存在或无法完成功能返回 `FAILED`。沿用各库已有错误命名；不要为了统一文字而破坏已有 ABI。任何异步完成都带请求 id 和 generation，迟到完成不能覆盖新资源。

## 7. 实施顺序

1. P0 构建回归。
2. P1 → P2/P3；P4/P5 可与前三者并行。
3. P6 与 P7，验证 Vulkan/OpenGL 路径和输入后端。
4. P8/P9/P10/P11，按公共依赖拆分，彼此独立的模块并行。
5. P12 集成，随后做全量 normal、ASan+UBSan、TSan、fuzz、图形和 CI 类似树验证。
6. 独立代码评审、处理评审发现、同步远程冲突、提交并直接推送 `origin/master`，检查远程 CI。

每个子项目另写具体 API 计划，不以本总体文档代替逐步 TDD 记录。提交按子项目划分，已完成行为立即在 `docs/Implementation_Status.md` 顶部和对应设计文档更新。

## 8. 验收标准

- 所有 P0–P12 的行为均有生产实现和直接调用测试，不是仅设计或桩。
- 新增测试先看到目标行为失败，再转绿；关键防护有变异证据。没有独立见过红的测试需注明。
- 普通、ASan+UBSan、TSan 全量非图形测试通过；图形测试、确定性 fuzz smoke 和无 Snowflake 的 CI 类似树通过。
- `git diff --check` 通过，工作树无未提交源文件；提交前同步远程并处理冲突。
- 代码评审覆盖本轮新增模块，发现均修复或记录明确的阻塞原因。
- 提交和推送后检查主 CI、Windows D3D12；跨平台失败不能视为完成。
- 真机、部署或听测没有实际执行时，文档保留限制，不以单元测试替代。

## 9. 默认决定

- 自动执行模式下不再逐个询问模块取舍；按用户“实现所有没有实现的内容”纳入旧范围外项。
- 以行为覆盖而非完整 CryENGINE 私有实现兼容作为交付边界，所有行为列在第 5 节，不再保留一张“同类功能永远不做”的排除表。
- 保留现有文档，追加或修正过期内容，不整篇覆盖历史记录。
- 不创建 PR；测试和评审完成后提交并直接合并到远程主分支。
