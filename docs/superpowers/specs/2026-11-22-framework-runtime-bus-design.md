# C++ 应用接入可选运行时总线设计

日期：2026-11-22

## 目标与边界

为 `framework/common` 提供真实可用的总线消费入口，让 C++ 应用在其 `Tick()` 调用线程接收并解析 IO 完成通知。该子项目只交付订阅、生命周期、类型化回调、诊断计数及构建集成，不创建额外线程，不取得全局 IO facade、ECS、渲染资源或网络状态的所有权，也不扩展其他消息类型。

现有 `BaseApplication`、`ApplicationInterface` 和默认 `empty` 可执行文件保持原行为；默认框架构建不配置引擎，不生成或链接运行时桥接库。项目保持 C11 引擎与 C++20 框架的现行标准，旧文档中的 C++11 描述只追加澄清，不回退工具链。

## 方案比较

1. **可选派生类与独立库（采用）**：新增 `bk::RuntimeBusApplication` 和 `common_runtime`。只有显式链接该库的应用承担 `runtime_core`、`engine` 和线程依赖。优点是默认边界不变，C/C++ ABI 有真实链接测试；代价是需要维护一个窄适配层。
2. **直接扩展 `BaseApplication`**：修改现有头文件和 `common`。调用路径短，但默认应用必须看见运行时头文件或携带条件编译、弱符号等额外机制，跨平台依赖与行为风险较高，因此不采用。
3. **只修订文档**：可以澄清历史状态，却没有 C++ 消费实现，不能完成本项功能，因此不采用。

## 组件与构建

新增 `framework/common/runtime_bus_application.h` 与对应 `.cc`。派生类继承 `BaseApplication`，公共头文件只在可选库中使用，可包含运行时 C 头文件并复用 `BreakRuntimeError`、`BreakRuntimeIoNotice` 等既有类型。

`common_runtime` 是显式可选静态库，链接 `common`、`runtime_core`、`engine` 和平台线程库。引擎构建启用测试时加入 `framework/common`，以便针对正式库运行 C++20 测试；现有引擎及示例程序不链接 `common_runtime`。根构建增加默认关闭的 `BREAK_FRAMEWORK_ENABLE_RUNTIME`：启用时先配置引擎再配置框架；默认路径仍只有 `common` 与 `empty`。根启用路径中的引擎测试默认关闭，调用方可显式覆盖，避免可选桥接无条件拉起整棵测试树。

## 公共行为

- `AttachRuntimeBus(bus)` 仅记录借用指针。空指针、重复挂接、初始化后挂接均拒绝；总线必须比挂接关系更长寿。它不接管总线，也不改变进程级 IO bus attachment。
- `Init()` 先运行基类初始化；有挂接总线时创建 64 槽、16 个控制预留槽的自有队列，再订阅 `BREAK_RUNTIME_IO_NOTICE_KIND`。kind 必须已经由 IO 侧或同等初始化方登记；适配类不复制 kind 注册策略。重复初始化拒绝。
- `Tick()` 先执行基类入口，再非阻塞排空队列。每条消息都由 `break_runtime_io_notice_view` 校验 kind、版本和长度。合法通知递增接收计数并调用受保护的 `OnRuntimeIoNotice(const BreakRuntimeIoNotice&)`；默认回调为空，派生应用可覆盖。回调只发生在调用 `Tick()` 的线程。畸形通知递增畸形计数，不进入回调。所有消息都在处理后释放。
- `DetachRuntimeBus()` 先同步退订，再销毁队列，最后清除借用指针。运行中解除后不再接收通知，但要到下一次初始化前才能重新挂接。重复解除安全。
- `DeInit()` 幂等，执行解除并调用基类清理。析构调用相同路径。初始化失败会回收部分建立的订阅与队列、恢复未初始化状态并保留借用总线，修复外部条件后可直接重试；统计在新的初始化尝试开始时清零。

适配类不拥有 IO worker 的关停顺序。完整应用仍须先停止相关生产者，再销毁总线；单独解除订阅是安全的，因为总线的 `unsubscribe` 返回后不会再访问该队列。公共方法及统计快照只在应用所有者线程调用，不提供跨线程热切换。

## 错误与诊断

初始化直接把对应 `BreakRuntimeError` 数值作为非零 `int` 返回；基类错误原样返回。队列创建失败、kind 未登记和订阅表满都走同一清理路径。关闭且排空的队列结束本帧排空，其他意外轮询错误也停止排空而不重试同一条消息。

`RuntimeBusApplicationStats` 提供累计合法 IO 通知数和畸形通知数。队列丢弃与高水位继续使用总线既有订阅统计，不复制另一套计数。适配类不吞掉合法通知中的失败状态；通知值原样交给派生应用决策。

## TDD 验收

先写 C++20 行为测试并观察缺少接口时的预期失败，再实现最小代码。至少覆盖：

1. 无挂接时 `Init/Tick/DeInit` 与基类默认行为一致，重复清理和析构安全。
2. 空总线、重复挂接、初始化后挂接、重复初始化均被拒绝。
3. kind 未登记和订阅表满导致初始化失败；移除外部障碍后同一对象重试成功，退订与队列资源无泄漏。
4. 真实总线发布成功、失败与取消状态的通知，回调字段、顺序、线程身份和统计准确；一次 `Tick()` 处理当前队列内全部通知。
5. 错误 kind、版本、长度和空载荷不会触发回调，且消息引用正确释放。
6. 解除后、清理后以及析构后不再投递；同一对象可重新挂接并再次初始化。
7. 队列满时总线报告丢弃而非阻塞；应用恢复排空后可继续接收后续通知。
8. 正式 `common_runtime` 与生产 `runtime_core` 完成 C++20 编译和链接，调用真实 IO 通知解析 ABI；默认根构建仍成功且没有桥接目标。

通过后追加运行时消息设计、缺失能力和实现状态文档。完成独立代码评审、默认框架构建、双图形后端回归、ASan/UBSan、相关 TSan 与 fuzz；随后验证可用的平台矩阵，解决冲突后直接提交并推送 `master`，不创建 PR。

## 假设

- 用户已要求继续既定计划并在自动模式下执行，因此本设计采用上述推荐方案，不暂停等待逐项选择。
- 本批只订阅 IO 通知，其他类型各有独立所有权与协议，留待各自子项目。
- 默认 `empty` 不改成桥接派生类；真实消费由测试派生应用和后续显式选择 `common_runtime` 的应用完成。
