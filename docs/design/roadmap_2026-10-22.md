# Break Runtime Expansion Roadmap

## Purpose

This roadmap decomposes the requested architecture/runtime/editor/operations work into independently reviewable subprojects. It preserves the current C11 engine core, C++11 application/editor layer, Lua scripting choice, existing myui/RHI/platform/task/profiler infrastructure, and the evidence-first documentation policy.

## Ground Rules

- C11 remains the runtime core language; C++11 remains the application/editor layer.
- Lua is the only planned runtime scripting language. Zig is not introduced as a gameplay scripting dependency.
- Main/Game owns mutable World/ECS/script state. Other domains communicate through owned messages, command queues, snapshots, or fences.
- Network callbacks validate/copy/enqueue; they do not call gameplay, ECS, Lua, UI, or RHI.
- Runtime changes require a focused test before implementation and normal/ASan/TSan validation where supported.
- Documentation must distinguish formal runtime targets from focused/test-only targets.
- Runtime Core's global lifecycle is `CREATED -> STARTING -> RUNNING -> QUIESCING -> DRAINING -> STOPPING -> STOPPED/FAILED`; subsystem states are local mappings only, coordinated by one Runtime coordinator.
- Runtime Core formal queues return non-blocking `BREAK_RUNTIME_OVERLOAD` when full; Network/IO/Audio/RHI hot paths never inline. Legacy compatibility behavior, including Task legacy inline fallback, remains separately documented.
- Stage 2 examples use project types `u8/u16/u32/u64/usize` from `engine/src/core/types.h`.
- No subproject may silently claim crash upload, online updates, anti-cheat, distributed World Partition, or production editor integration before its own acceptance tests pass.
