## Known gaps (stated as measured, not hidden)

Every miss category below was traced to a root cause. Defects in the new scripts (extract_shaders / extract_cvars /
gen_catalog) were fixed and the runs repeated until stable. extract_api.py (C++ headers) is frozen by project rule:
its defects are only reported here, and they are what keeps the C++ numbers below 100%.

### C++ (extract_api.py — not modified, defects reported only)

1. **Declaration right after a `MACRO(...)` line with no semicolon gets swallowed.** universal-ctags treats
   `SLATE_END_ARGS()`, `RIGVM_METHOD()`, `DECLARE_RIG_METADATA_METHODS(T)`, `DEPRECATED_CHARACTER_MOVEMENT_RPC(a,b)`,
   `SHADER_USE_PARAMETER_STRUCT(...)` and similar as the start of the next declaration. The index then records the
   **macro name** as the prototype/function name (e.g. `SLATE_BEGIN_ARGS` 3488 times, `RIGVM_METHOD` 1354 times;
   18,074 of 765,181 prototype/function rows are named like a macro), and the real name (`Construct`, `Execute`,
   `ServerMove`, `SetMenuContent` …) never reaches the index. The declaration text is usually still in the
   Markdown (see the "declaration text present in Markdown" row). This is the main cause of the 0.97% function-
   sample misses and of the `UFUNCTION` misses in `Character.h`.
2. **`UPARAM(...)` inside parameter lists.** ctags parses `UPARAM(ref) T& X` as the function name, so the index
   records the prototype as `UPARAM` (857 rows) and the real function name is lost (e.g.
   `UEditableText::SetIsPassword`, Niagara/PhysicsControl BP libraries). The UFUNCTION is attached to the
   `UPARAM` row, not to the function.
3. **`TEnumAsByte<enum E>` members.** The `enum` keyword inside a template argument makes ctags drop the member
   (≈365 of the remaining UPROPERTY misses, e.g. `EngineTypes.h` `FResponseChannel::Response`,
   `LegacyCameraShake.h`).
4. **`UE_EXPERIMENTAL(ver, "msg")` / `UE_DEPRECATED(...)` before a member or class head** sometimes hides the next
   member (`MotionWarpingComponent.h:263-283`). It also hides `class UE_DEPRECATED(...) X` heads, which
   gen_catalog works around on its own side.
5. **Members whose initialiser is a braced literal with `{ }`** (`FVector2dCameraParameter Speed = FVector2d{1,1};`)
   can end the member list early in ctags; the members after that point are missing.
6. **Files with 0 symbols:** 663 of the 46,255 headers render "no declarations extracted". The independent scanner
   finds real declarations in only 24 of them: 20 PluginBrowser/AudioInsights **template headers** (the
   `PLUGIN_NAME` placeholder is not valid C++, and the module named `PLUGIN_NAME` is shared by two templates, so one
   overwrites the other, which also explains the 20 headers "missing" from the Markdown) and 4 USD codegen
   `schemaClass.h` templates under `Resources/`. The rest are pure `#include`/`#define` aggregators or X-macro list
   files (macro invocations only).
7. **Known from before:** an enumerator's doc comment is only taken from the line above or a trailing comment, so
   multi-line trailing comments are lost. `#define`-generated types (IMPLEMENT_GLOBAL_SHADER etc.) are not expanded.
   The 19 NoModule groups are SDK/third-party code.
8. Minor: `#if 0` blocks are indexed by ctags as if they were live code (the coverage scanner excludes them). The
   module list in modules.json counts 2369 named modules for 2524 Build.cs outside ThirdParty: Build.cs files that
   share a directory, platform-extension Build.cs files with no headers of their own, and the `PLUGIN_NAME` name
   collision make up the difference. dictionary/modules.tsv lists all 2747 Build.cs files.
